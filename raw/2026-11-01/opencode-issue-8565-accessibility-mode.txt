### Describe the enhancement you want to request

At the moment, Opencode is actively hostile to any screen readers trying to use the TUI. Emojis, animations and unicode characters add extra noise the text to speech voice is reading to a blind user, which are only there for visual effects in the first place. An accessibility mode would remove those and replace them with more textual equivalents, for instance the spinner being changed to some text when the AI is working and not constantly updating, as this makes the screen reader's review focus jump to the bottom of the window or close to it every time a text update happens.

User: king-dahmanus
Message: This is an expansion of this feature request to hopefully make it more likely to be implemented:

The Opencode GUI is not accessible to screen readers, agent messages can't be read and I didn't explore further beyond that to determin the specifics since it's unusable.

TUI is a bit better. Messages can be read somewhat, agent questions can be answered with some mental gymnastics like remembering that the first option doesn't actually get announced and gets a duplicate of the second option. Also, without an external Addon for the NVDA screen reader that only accidentally improves experience of Opencode because it's just called Terminal Access, we can't actually read the messages without moving the mouse randomly up and down until it focuses on the window and reads the whole screen from top to bottom (every new session alert, every context report, every todo item even when it's actually buggy and shows random bits of outdated statistics instead of a handful of real todo items).

Here's a list of some issues with accessibility:
•When a question appears, the first option does not get read even when focused with the cursor using up and down arrow keys.
•Menus, such as the model selection and session switching, are inaccessible. No announcement of the currently focused item, the only way to know is to read the full terminal until the screen reader interrupts a random line with a recognizable element of the menu in question (fri 31 July, Big Pickle). This approach does not actually tell whether things like "search" are clickable and thus the first item, or whether they are unfocusable headings, so selection entails a lot of mental guesswork.
•No ability to read the current happenings while the agent is thinking or executing except with a random NVDA addon that only worked by accident and was not designed for Opencode TUI.

Easy proposal: fix the bugs as they appear, and/or make an accessibility mode for the TUI specifically to trim constantly repeating elements like session info and context, menu accessibility enhancement, etc.

Hard proposal: remake the GUI to be accessible or have an accessibility mode where everything is properly supported, following the Web Content Accessibility Guidelines' standard, i.e: appropriate use of heading levels for message separation and message content, expandable/collapsable sections in buttons for thoughts and code execution, handling of slash commands, and so on.

Thank you for this great project, hope this issue gets resolved.
Regards.
