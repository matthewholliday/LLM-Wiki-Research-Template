Title: Windows: Screen reader accessibility missing completely
URL: https://github.com/zed-industries/zed/issues/41138
Description: Body: ### Summary

<!-- Please insert a one-line summary of the issue below -->
Zed is absolutely inaccessible for screen reader users on Windows. Tested with latest JAWS and NVDA versions.

### Description
<!--  Describe with sufficient detail to reproduce from a clean Zed install. -->
Steps to trigger the problem:
1. Install Zed on Windows 11.
2. run Zed with a screen reader. You may use free and open-source [NVDA screen reader](https://www.nvaccess.org/download/) for this test.
3. Try to… do something. I mean, like anything at all. You will get no feedback. Try arrowing up and down, pressing Tab, F6, some Zed commands (I don't know any of them because well, I cannot use the editor to learn it).

**Expected Behavior**: The editor should be accessible for screen readers. Probably it's impolite to mention competitors, but see how VS Code is done accessibility-wise.
**Actual Behavior**: Zed is absolutely silent. the only thing I could do (by intuition and Windows/VS Code habits) is pressing Ctrl+O. Of course, the native Windows dialog is accessible, but when I opened the folder, again nothing spoke.


### Zed Version and System Specs

**Note**! This info is provided by JAWS, my screen reader of choice, and by Windows built-in dialog. As Zed is not accessible, I cannot summon the command palette and get that info from there.
Zed Version 0.209.6
Microsoft Windows
Version 25H2 (OS Build 26200.6899)

User: mikayla-maki
Message: Hi @Menelion, thanks for bringing up this issue. We have a rough plan to integrate [AccessKit](https://github.com/AccessKit/accesskit) into GPUI and I've talked to the developers there about the project and some other UI framework maintainers. The main blocker is that I'm the only person at Zed who is interested in expanding our UI framework as a UI framework on it's own, and so simply haven't had the space to give this the attention this deserves. However, I hope to change that soon as we've recently hired another developer, @cameron1024, who has done a lot of work with screen readers for other frameworks.

To make the Zed accessible will take a few things:
- Start up an accesskit adapter and put that in GPUI somewhere
- Begin producing accesskit nodes as a side effect of rendering
- Research the associated accessibility APIs and add them to `div()` (e.g. how to associate ARIA roles with a given element, should be pretty straightforward)
- Go over Zed and use the new APIs

AccessKit is already seeing success with projects like egui and bevy, and the maintainers tell me that as long as we can produce a stable ID (we can) we shouldn't have any problems with it. We just gotta get it done :D

User: cameron1024
Message: Thanks for the offer @Almost-Senseless-Coder . It's definitely something I'm keen to support, and I feel optimistic about the path forward. 

A small status update: 
- #56065 is mostly working, and adds accesskit support into GPUI. The core primitives are in place and I believe most of the hard work is done. 
- There is a very small demo app that can be run with `cargo run -p gpui --example a11y` (note you may need extra feature flags on some platforms)
- I have tested on Windows using the `inspect` tool from VS and I was able to see and interact with UI elements
- I have tested on Linux Wayland with `accerciser` and also `pyatspi`, and was also able to see and interact with UI elements
- I have not tested on Linux X11, since I don't have a machine with X11 handy, but I plan to test in a VM, since my understanding is that X11 is in much more widespread use by users of assistive technologies (happy to be corrected on this assumption)
- I spoke to @DataTriny about MacOS support, and the issues I was having, and he mentioned to me that the Accessibility Inspector tool only works with app bundles. I briefly tested with VoiceOver on a colleague's Mac, and was able to see individual UI elements highlighted. However, after building an app bundle with some accessible UI elements inserted, I was not able to see them in the Accessibility Inspector.

Given all of the above, if anyone wants to try running the example app and giving feedback, that would be much appreciated, especially X11 and MacOS users. If you do, I think it would probably be better to leave those comments on #56065 directly, rather than in this issue, just to keep the thread tidy.

Thanks for your patience 😅
