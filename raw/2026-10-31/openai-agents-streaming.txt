Keep consuming `result.stream_events()` until the async iterator finishes. A streaming run is not complete until the iterator ends, and post-processing such as session persistence, approval bookkeeping, or history compaction can finish after the last visible token arrives. When the loop exits, `result.is_complete` reflects the final run state.

Streaming is compatible with runs that pause for tool approval. If a tool requires approval, `result.stream_events()` finishes and pending approvals are exposed in [`RunResultStreaming.interruptions`](https://openai.github.io/openai-agents-python/ref/result/#agents.result.RunResultStreaming.interruptions "interruptions            class-attribute       instance-attribute   "). Convert the result to a [`RunState`](https://openai.github.io/openai-agents-python/ref/run_state/#agents.run_state.RunState "RunState            dataclass   ") with `result.to_state()`, approve or reject the interruption, and then resume with `Runner.run_streamed(...)`.

if result.interruptions:
    state = result.to_state()
    for interruption in result.interruptions:
        state.approve(interruption)
    result = Runner.run_streamed(agent, state)
    async for _event in result.stream_events():
        pass
```

## Cancel streaming after the current turn

If you need to stop a streaming run in the middle, call [`result.cancel()`](https://openai.github.io/openai-agents-python/ref/result/#agents.result.RunResultStreaming.cancel "cancel"). By default this stops the run immediately. To let the current turn finish cleanly before stopping, call `result.cancel(mode="after_turn")` instead.

A streamed run is not complete until `result.stream_events()` finishes. The SDK may still be persisting session items, finalizing approval state, or compacting history after the last visible token.

If you are manually continuing from [`result.to_input_list(mode="normalized")`](https://openai.github.io/openai-agents-python/ref/result/#agents.result.RunResultBase.to_input_list "to_input_list"), and `cancel(mode="after_turn")` stops after a tool turn, rerun `result.last_agent` with that normalized input to continue the unfinished existing user turn instead of appending a fresh user turn right away.

- If new user input arrives before that unfinished run resumes, convert the drained result with `result.to_state()`, call [`state.add_input(...)`](https://openai.github.io/openai-agents-python/ref/run_state/#agents.run_state.RunState.add_input "add_input"), and resume from the state. The runner admits the staged input immediately before the next model call; see [Add input before resuming](https://openai.github.io/openai-agents-python/results/#add-input-before-resuming).
- If a streamed run stopped for tool approval, do not treat that as a new turn. Finish draining the stream, inspect `result.interruptions`, and resume from `result.to_state()` instead.
- Use [`RunConfig.session_input_callback`](https://openai.github.io/openai-agents-python/ref/run/#agents.run.RunConfig.session_input_callback "session_input_callback            class-attribute       instance-attribute   ") to customize how retrieved session history and the new user input are merged before the next model call. If you rewrite new-turn items there, the rewritten version is what gets persisted for that turn.

The background run and the event consumer have separate lifetimes. If your application breaks out of the `async for` loop over events, raises an exception while handling an event, or cancels the consumer while it is handling an event, the run can continue making model and tool calls. Closing the event iterator with `aclose()` alone waits for the run to finish; it does not request cancellation. Cancellation while the consumer is awaiting the next event does request cancellation of the run, so do not rely on where cancellation happens to stop unwanted work.

When one consumer owns the run, explicitly cancel on early exit and wait for cleanup. In this example, `agent` is your agent and `forward(event)` is your application's asynchronous event handler:

result = Runner.run_streamed(agent, input="Please tell me 5 jokes.")
events = result.stream_events()
exhausted = False
try:
    async for event in events:
        await forward(event)
    else:
        exhausted = True
finally:
    if not exhausted:
        result.cancel()
        await events.aclose()
        # Use a fresh iterator in case cancellation already closed the original.
        async for _event in result.stream_events():
            pass
```

Normal exhaustion leaves the result unchanged. An early `break`, a handler exception, or consumer cancellation enters the cleanup block. `cancel()` requests cancellation; consuming the cleanup stream runs the SDK's stream cleanup path. Neither `result.is_complete` nor finishing the cleanup stream guarantees that every asynchronous finalizer inside a tool has finished. Applications that depend on those finalizers must track and await tool cleanup separately.

This example assumes one consumer and cooperative asynchronous tools. A further cancellation during cleanup can interrupt the cleanup block, and a cleanup failure can replace the original exception. Applications that must handle those cases need a supervised cleanup task and an explicit error-handling policy. Cancellation cannot undo tool effects that have already happened.
